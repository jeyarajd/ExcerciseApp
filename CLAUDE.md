# Floor Age

Native iOS app (SwiftUI, RealityKit, iOS 18+). Fully offline: no server, no AI, no accounts. See README.md for features and setup.

## Build

- The Xcode project is generated: `xcodegen generate` (from `project.yml`). Never commit `*.xcodeproj` or `FloorAge/Info.plist`.
- Development usually happens on Windows without a Mac. Compile checks run on GitHub Actions (`.github/workflows/ios-build.yml`, runner `macos-26`). Read failures with `gh run view --log-failed`, and download simulator screenshots with `gh run download`.
- On a Mac: `xcodebuild build -project FloorAge.xcodeproj -scheme FloorAge -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO`.
- Swift language mode is 5 (`SWIFT_VERSION: "5.0"`). Models are `ObservableObject` classes, not `@Observable`.
- Unit tests live in `FloorAgeTests/` (target `FloorAgeTests` in `project.yml`); CI runs `xcodebuild test`.

## Avatar

- `FloorAge/Resources/exercises.json` is the single source of truth for the skeleton, poses and exercises. `tools/pose_preview.py` and `FloorAge/Avatar/PoseAnimator.swift` implement the same FK, ground solver and blending. Change both together.
- Euler order: `q = qx * qz * qy` (twist Y first, then Z, then X). For a limb pointing down, negative X swings it forward. For the spine, positive X bends forward. Left is +X.
- After editing poses, run `python tools/pose_preview.py <id>` and look at `tools/out/<id>.png` before committing.
- Two coach bodies share the poses: `AvatarRig` (stylized, built in code) and `RealisticCoach` (MakeHuman USDZ, skeleton retargeted each frame). Both conform to `CoachBody`. The coach's gender follows `Profile.gender` (`CoachLook`); the style is a setting (`CoachStyle`).
- Realistic models are generated by `tools/build_coach.py` (Blender + MPFB, CC0 assets only). Keep opaque materials free of opacity and cut-outs on mask textures: RealityKit misreads USD alpha.
- Keyframes can carry a `cue` ("Squeeze and lift"), shown and spoken on time during a session.
- Demo launch arguments for screenshots: `-demoExercise <id> -demoTime <seconds>`, or (Debug builds) `-demoScreen <name>` (see `DemoScreen`, e.g. today, track, plan, test, sitRise, balance, chairStand, reach, cameraChair, result, share, plus, family, familyAdd, challenge, badge, drop, widgets), `-demoPlus NO` to show Plus locked with sample data, `-coachLook female|male`, `-voiceEnabled NO`, and `-demoSnapshot <file.png>` to save a picture and quit.

## Conventions

- Localisation: English default, Hindi and Spanish (see README "Translations"). User-facing text built in code must use `String(localized:)`, and so must every spoken line (`voice.say`). Never put a raw `Double` inside `String(localized:)` (it prints "24.900000"); format it first. Exercise and food text come from the `Exercises`/`Foods` tables (English stays the stored key). Run `python3 tools/check_translations.py` after adding strings.
- Keep all personal data on the device (`AppModel` JSON file). The app makes no network requests of its own. The only exception is StoreKit, which talks to Apple for the Floor Age Plus purchase.
- Family profiles: `AppModel` holds the active member's data. The owner keeps the original `floorage.json`, each family member gets `floorage-<uuid>.json`, and `floorage-family.json` indexes them; that index only exists once there is more than one person. Phone-sensor data (steps, Apple Health sleep, reminders) follows the owner only (`model.isOwner`). Adding or switching to family members needs Plus. `FamilyTests` cover this.
- Camera scoring: `Models/PoseScoring.swift` holds the pure logic (`ChairStandCounter`, `BalanceDetector`, `ReachEstimator`, tested with `BodyPose.sample`). `Features/Test/PoseCamera.swift` runs the front camera and Vision, and draws the mannequin outline (`BodyOverlay`) in the small camera picture. Frames are never stored. `Models/PoseMirror.swift` turns each 2D pose into rig angles, estimating depth from bone lengths (side-on views face the coach the way the person faces), and `AvatarController.follow(_:)` makes the coach copy it live. `PoseMirrorTests` check standing, sitting, lifting a foot and folding. `-demoScreen cameraChair|cameraBalance|cameraReach` plays scripted poses; add `-demoPhase <seconds>` to capture a later moment.
- Share card: `Features/Test/ShareCard.swift` renders 1080×1920. Set `AppLinks.appStoreID` after launch to add the QR code and link.
- App Store listing: `fastlane/metadata/` (check with `tools/check_appstore_metadata.py`) and `AppStore/LISTING.md`.
- Widgets: `FloorAgeWidgets` target (App Group `group.com.jeyaraj.floorage`). `App/SnapshotSync.swift` writes a `FloorAgeSnapshot` (`Models/SharedSnapshot.swift`, owner only, debounced) and reloads the timelines. Widgets roll it forward to the current day and read steps from CoreMotion. Tapping opens `floorage://today|steps`.
- Apple Watch: `FloorAgeWatch` target (watchOS 11, single-target app embedded in the iOS app). Messages are in `Models/WatchMessages.swift`: the iPhone side is `App/WatchLink.swift`, the Watch side `FloorAgeWatch/PhoneLink.swift`. Chair stands on the wrist use `WristRepCounter` (`Models/WristMotion.swift`, tested). Simulator builds skip the Watch icon because it needs a watchOS runtime; device and archive builds need the watchOS platform installed (TestFlight downloads it). So do `clean` and `test` on the scheme: CI builds everything first, then regenerates without the Watch dependency for tests and screenshots.
- Apple Health: `Features/Health/AppleHealth.swift` saves workouts and reads steps (owner only, both opt-in in Settings). Energy is MET × kg × hours (`Calories.burned`).
- 30-day challenge and retest: `Models/Challenge.swift` (`Challenge`, `Retest`). `AppModel.newBadge` drives the confetti overlay in `RootView`. `Reminders.scheduleRetest` sets one reminder 28 days after the last check.
- Floor Age Plus is one non-consumable in-app purchase (`Store`, product `com.jeyaraj.floorage.plus`, test file `FloorAge.storekit`). Plus features are listed in `PlusFeature`: check `store.hasPlus` and show `PlusLockedCard` when locked. Never put safety guidance, the Floor Age check or the daily coached session behind Plus. Keep a Restore Purchases button reachable, because App Review requires it.
- New fields in `AppModel.Stored` and `Profile` must be optional (or have defaults), so files saved by older versions still decode. `TrackingStorageTests.testFilesFromTheOlderVersionStillLoad` guards this.
- Screens use `AppBackground()` (or `.appBackground()` on List/Form). Content blocks use `.heroCard(Feature)` for the headline figure (gradient, white text), `.tintedCard(Feature)` for supporting cards, and `.card()` for neutral ones. `FeatureBadge`, `ArcGauge`, `Font.display` and `Font.metric` complete the look (`App/Theme.swift`). Keep each feature on its own `Feature` colours. The 3D view is transparent so the coach stands on that background.
- Food photos: `FoodRecognizer` maps Vision's built-in `VNClassifyImageRequest` labels to `FoodLibrary` names (`suggestions`); every mapped name must exist in `FoodLibrary` (tested). Photos are never stored.
- `TrainingPlan` (Models) builds each week from the profile. Every number traces to a source listed in its header comment and in `PlanView`; keep them in step. `TrainingPlanTests` checks the Couch to 5K intervals against the NHS plan.
- Reminders: call `model.refreshReminders()` after anything that changes what's done or planned (`App/ReminderSync.swift`). `AppModel.reminderText(on:)` decides each day's message (nil = no reminder).
- Sleep: `SleepGuide.nights(from:)` merges Apple Health samples (tested without HealthKit). HealthKit is read-only (`HealthSleep`), with the entitlement generated from `project.yml`. Screenshots built for Mac need `CODE_SIGN_ENTITLEMENTS=` because ad-hoc-signed apps can't carry it.
- `StepCounter` uses CoreMotion's pedometer (iOS only; step counting isn't available in the Simulator, so screenshots use `StepCounter.sample()`).
- Demo videos are bundled as `FloorAge/Resources/Videos/demo_<exercise id>.mp4` (`DemoVideo`). They're optional per exercise, and the 3D coach still drives sessions and rep counting. The current clips are placeholders.
- Floor Age is a fitness estimate, never medical advice. Keep safety copy and limitation filtering (`PlanBuilder.unsafe`) intact when adding exercises.
